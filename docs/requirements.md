# Требования и текущее покрытие

Источник требований — [`backend/services/incidents.md`](../../backend/services/incidents.md)
и задачи INC-1–INC-9 в [`backend/tasks.md`](../../backend/tasks.md). Этот
документ описывает наличие кода, не подтверждает эксплуатационную готовность.

| Область | Текущее состояние |
|---|---|
| Модель и миграции | Модели и ревизии Alembic присутствуют; применять до запуска API |
| Ручные инциденты, Review, расследования | Маршруты и сервисы реализованы; PostgreSQL integration и Docker smoke с `/health`/`/ready` прошли |
| Алерты | Consumer, квитанции, дедупликация, правила корреляции, квоты и автостарт реализованы; живой источник снимков `projects` ещё не подключён |
| AI | Dispatch, callbacks и чтение результатов присутствуют; сквозной прогон с живым AI Backend не подтверждён |
| События | Outbox и relay присутствуют; потребители realtime/notifications подключаются отдельно |
| Удаление проекта | Consumer `project.deleting` удаляет данные порциями, пишет `cleanup.completed`; повтор и защита от нового ручного инцидента проверены на PostgreSQL |

Счётчики `GET /api/v1/overview` и AI context прошли HTTP-проверки
на PostgreSQL с подменой projects. Overview требует явного `project_id`
по описанию сервиса, хотя общий OpenAPI сейчас помечает параметр
необязательным. Для живого overview нужен маршрут топологии projects.
Для полного AI context нужен внутренний источник каталога и выкаток.
Запуск против живых
соседних сервисов зависит от совместимых версий auth (служебные токены),
projects (ACL, ingest-токены, снимки конфигурации), aiip-kit, RabbitMQ
и AI Backend. Требования к их контрактам зафиксированы в
`backend/decisions.md`, `backend/messaging.md` и `docs/contracts/` общего
рабочего дерева. Проверки совместимости и нагрузочный прогон остаются
отдельной работой.
